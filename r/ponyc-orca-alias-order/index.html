ponylang/ponyc #6696 · fix-orca-alias-order · a4f6a7ec6

Fix garbage collection when a tag aliases a val or iso reference

Objects reachable through a val or iso now stay alive even when the garbage collector reaches the same object through a tag first.
25 files changed+1,509−151

Motivation

A tag gives access to an object's identity only. The collector can count the object without following its fields. Previously, that visit could also suppress field tracing through a later readable alias, leaving reachable children eligible for collection.

Behavioral Changes

An actor can use data reachable through a readable reference even if the collector first encounters a tag for the same object. This applies to references in messages and in the actor’s own fields.

Performance on perf-tester

Five of the eight workloads below ran 1.0–3.2% slower than main at f825c387d. The other three weren't distinguishable from main.

The runs were on perf-tester (x86-64 Linux, Ryzen 9 5950X, SMT off), comparing main with main plus this PR's GC changes. Each build ran at three code layouts, with 0, 16, or 48 bytes of padding early in the runtime so the code after it sits at different addresses, because code placement alone moved timings by several percent in earlier runs. After a warm-up, every build was run once per workload in each of 12 rounds, in a random order. A result counts only if, at every layout, at least 10 of the 12 per-round ratios were on the same side of no change, and that side was the same at all three layouts. Workloads where one actor runs at a time ran on one pinned scheduler thread; message-ubench ran on 8. Each change below is the median time change against main, given as the range across the three layouts.

On the seven workloads that do a fixed amount of work, instructions retired stayed within about 1.7% of main, except send-to-self at +4.9%. Outside send-to-self, the time cost isn't extra instructions. (message-ubench runs for a fixed time, so its instruction count follows how much work it did.)

None of the workloads in the table visits an object through a tag before a readable reference, the order the bug was about. The tag-then-val workload does. In one message, an actor sent a val array and a tag array over the same 10,000 objects, ordered so each object was traced as a tag first and then as a val. On main, the collector skipped each object's fields on the val visit. That's the bug. With this PR, the tag-then-val workload took about 21% longer and retired about 18% more instructions than on main.

With this PR, each object's fields are traced exactly once in either order. The tag-then-val order cost 1.7–1.8% more instructions and about 3% more time than the val-then-tag order. That difference is the cost of tracing the fields on the later visit instead of the first.

With #6697's pagemap cache ("Speed up sending objects between actors"), six of the same Linux workloads were 2.4–6.0% faster than main. On perf-tester, this fix together with the cache, measured against the same main at f825c387d, which predates #6697, was not slower on any of the eight workloads in the table: 1.4–4.5% faster on the iso array, send-to-self, and the val array of tag references, and not distinguishable on the rest. That run used an earlier version of the cache; the version merged in #6697 compiles to the same x86-64 Linux instructions for ponyint_pagemap_get. The cache is off on macOS in #6697, and this fix wasn't measured on macOS, Windows, arm64, or 32-bit. The combined build was slower only on the tag-then-val workload, where the extra work is the fix.

Architecture

Counting an object and tracing its fields

On the first visit, begin_visit records whether the reference was opaque. A later val or iso can then trigger the field tracing its capability requires. Repeated aliases add no further message credit.

When an opaque visit borrows reference-count credit for a remote object, a later val updates the pending acquire with the object's type and immutability. The actor borrows only once. If it already held credit before the loan, it also traces the fields to protect them until the owner receives the acquire.

Regression tests

The runtime tests check alias order during send, receive, and remote marking. They also check that a self-send pins an object once per message, that the owner receives immutable credit, and that old visit marks expire. A compiled Pony test sends two objects with only scalar fields, one in each alias order. It checks the immutable flag and one outstanding reference per object after send, then zero outstanding references after receive. A second Pony program sends two parents to another actor, one as val and one as iso, and keeps a tag to each. It checks that both children survive garbage collection before the send and while the receiving actor holds the parents. After that actor drops both references, the program checks that each child’s finaliser runs exactly once. Five more compiled Pony programs reach one object through a tag before reaching it through a val or iso. Two send it in a message, and three hold it in actor fields and force a garbage collection. Each checks that the child object is still counted, or still in the actor's foreign map, afterwards.

Release Notes

Fix garbage collection when a tag aliases a val or iso reference

A Pony program could crash because the garbage collector freed data an actor could still reach. This could happen when the actor held a tag reference to an object and could also read that object's fields through another reference. The two references could be in the actor's own fields or in a message it sent or received, such as a message carrying both a tag and a val or iso. The runtime now keeps the data alive while the actor can still reach it.

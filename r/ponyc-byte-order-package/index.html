Add byte_order standard library package

New byte_order package with BigEndian and LittleEndian primitives for reading and writing multi-byte values in a specific byte order.
6 files changed +858 −0

Motivation

Closes ponylang/rfcs#112. Binary protocols and file formats require reading and writing integers in a specified byte order. Without a stdlib package, every project implements its own byte-swapping logic.

Read methods are generic over ReadSeq[U8], so they work with any byte sequence type. When the concrete type is Array[U8], iftype specialization selects an optimized path that uses native-width loads and conditional byte swaps. The generic path uses shift-and-OR.

Behavioral Changes

A new use "byte_order" import becomes available. The package provides two primitives that convert between native integers and their big-endian or little-endian byte representations.

Each primitive has 22 public methods: 10 read methods (U16, U32, U64, U128, I16, I32, I64, I128, F32, F64) that decode from a byte sequence, and 10 write methods that encode by appending bytes to an Array[U8]. Unsigned read methods (u16, u32, u64, u128) each have an iftype-specialized variant for Array[U8] that uses native-width loads and byte swaps instead of the generic shift-and-OR path. Signed reads delegate to unsigned, float reads delegate via bits()/from_bits().

All read methods are partial — they raise an error when the sequence has too few bytes at the given offset.

Architecture

Both primitives are stateless and share the same structure. Read methods dispatch at compile time via iftype specialization:

Signed reads (i16–i128) delegate to the unsigned read and cast. Float reads (f32, f64) delegate via bits()/from_bits(). Write methods are the inverse: signed and float writes delegate to unsigned, which pushes individual bytes in the appropriate order.

The difference between BigEndian and LittleEndian is two-fold: the ifdef guard checks bigendian vs. littleendian in the Array path, and the shift-and-OR generic path reverses which end of the value the low-offset bytes map to.

Release Notes

Add byte_order standard library package

A new byte_order package provides BigEndian and LittleEndian primitives for converting multi-byte values to and from their wire representation.

Read methods decode from any ReadSeq[U8] source (with an optimized path for Array[U8]). Write methods append encoded bytes to an Array[U8]. Both primitives cover U16–U128, their signed counterparts, and F32/F64.

use "byte_order"

// Encode a U32 in network (big-endian) order
let buf = Array[U8]
BigEndian.push_u32(buf, 0xDEADBEEF)
// buf is now [0xDE; 0xAD; 0xBE; 0xEF]

// Decode it back
let value = BigEndian.u32[Array[U8] box](buf)?  // 0xDEADBEEF

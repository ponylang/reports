Use forward slash as the path separator on all platforms

All paths in the files package and the compiler internals now use / as the separator on every platform, including Windows.
23 files changed +293 −306

Motivation

Cross-platform path code required every layer to normalize separators independently. The C runtime, the compiler, the stdlib, and each tool all had their own #ifdef blocks choosing \ on Windows and / elsewhere. Missing one meant backslashes leaking through on Windows, causing silent lookup failures when one layer stored a path with \ and another searched for it with /.

This PR makes / the canonical separator everywhere: the C runtime normalizes at ingress, the compiler does the same, Path.sep() returns "/" unconditionally, and Path.clean() converts any remaining \ on Windows.

Behavioral Changes

Paths are /-separated on all platforms

Path.sep() returns "/" on Windows (previously "\\"). Path.cwd(), Path.canonical(), Path.join(), Path.clean(), and all other path operations produce /-separated paths. Windows code that compared paths against string literals with \ will stop matching.

Path.normcase() only lowercases

On Windows, normcase() previously replaced / with \ and lowercased the path. It now only lowercases.

Path.from_slash() and Path.to_slash() removed

These functions served no purpose when all paths are already /-separated. Any code calling them will fail to compile.

Path.to_os() added

Converts / to \ on Windows. Returns the path unchanged on other platforms.

Windows cmd.exe footgun: cmd.exe interprets / as an option flag, not a path separator. Code that passes paths to cmd.exe or .bat files must wrap them with Path.to_os() to convert back to \. Win32 API calls accept / without issue — the footgun is specifically at the shell boundary.

dir(), base(), ext(), split() handle both separators on Windows

These functions now use an internal _rfind_sep helper that finds both / and \ on Windows. Paths from external sources (e.g. __loc.file()) that still contain \ are handled correctly without requiring a prior clean().

Architecture

The change normalizes paths at four ingress points. Everything downstream receives /-separated paths without needing its own normalization.

Release Notes

Use forward slash as the path separator on all platforms

All paths in the files package now use / as the separator on every platform, including Windows. Paths from Path.cwd() and Path.canonical() are /-separated, Path.sep() returns "/" unconditionally, and Path.clean() converts \ to / on Windows.

Path.is_sep() still accepts \ on Windows for parsing external input. Use Path.to_os() when a backslash path is needed for Windows shell commands.

Path.normcase() now only lowercases the path on case-insensitive platforms. It no longer replaces / with \ on Windows.

Before:

if path == "C:\\Users\\me\\project" then
  // ...
end

After:

if path == "C:/Users/me/project" then
  // ...
end

Code that passes paths to Windows shell commands should use Path.to_os():

let os_path = Path.to_os(path)

Remove Path.from_slash and Path.to_slash

Path.from_slash() and Path.to_slash() have been removed. All paths use / as the separator on every platform, so these functions served no purpose. Remove any calls to them.
